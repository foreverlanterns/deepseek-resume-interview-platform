## 1. 项目基线

- 课题：基于 DeepSeek 的智能简历诊断与面试模拟平台设计与实现。
- 前端：Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + ECharts。
- 后端：Python 3.13 + FastAPI + Pydantic v2 + SQLAlchemy 2 + Alembic。
- 数据库：PostgreSQL 17，正式方案不使用 SQLite。
- AI：DeepSeek 独立 Provider，接口、模型名、密钥全部走环境变量。
- 部署：Docker Compose + Nginx，MVP 不使用 Redis。

### 1.1 不可违背的约束

1. 四维诊断总分由程序按固定权重合成：格式 15%、完整度 20%、关键词 25%、JD 匹配 40%；LLM 只输出语义判断与证据，不直接给总分。
2. 修改示例禁止编造技能、公司、项目、证书或量化指标；缺失事实必须提示用户补充。
3. 每道面试题保存来源，例如 `resume:project[0]`、`jd:required_skill[2]`、`general:behavior`。
4. 不实现视频面试、表情识别、社区、UGC 题库、企业招聘端。
5. 前端只使用 TypeScript，不写纯 JavaScript。
6. API Key 只放后端 `.env`，不得提交；数据库只允许 PostgreSQL。
7. 历史对比只在同岗位、同面试类型、同 `rubric_version` 下进行，并保存 `prompt_version` 与模型名。
8. `reference/` 只读；复制 Apache-2.0 / MIT 代码必须保留许可证、NOTICE 并标注修改，优先重写。

### 4.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/resumes/upload` | `multipart/form-data`，字段名 `file`；返回 201 + 详情 |
| GET | `/api/v1/resumes` | 当前用户简历列表，按上传时间倒序，最多 100 条 |
| GET | `/api/v1/resumes/{id}` | 详情与 800 字文本预览 |
| DELETE | `/api/v1/resumes/{id}` | 删除记录与文件，204 |

错误码：

- 401：未登录或 Token 无效。
- 400：扩展名正确但内容不是有效 PDF/DOCX。
- 413：超过 `MAX_UPLOAD_SIZE_MB`（默认 10 MB）。
- 415：不是 PDF/DOCX（图片、DOC、TXT 等）。
- 404：简历不存在，或属于其他用户。

### 4.5 校验与安全设计

1. 文件类型以扩展名 + 文件头双重校验：PDF 必须以 `%PDF-` 开头；DOCX 必须是含 `word/document.xml` 与 `[Content_Types].xml` 的 ZIP。
2. 客户端 `Content-Type` 不参与判定；数据库 `mime_type` 由扩展名归一。
3. 存储路径只由 `user_id` / `resume_id` / 固定文件名组成，不使用用户文件名，避免路径穿越；文件名仅用于展示并已清洗。
4. 所有查询都带 `user_id` 条件；跨用户访问统一返回 404，不暴露资源是否存在。
5. 删除时先删除数据库记录，再在确认路径位于上传根目录内后递归删除简历目录。
6. 文本清洗移除 NUL、统一换行、压缩空白，并截断至 200,000 字符，保护数据库与后续 LLM 调用。
7. 扫描版 PDF（文本少于 50 字符）标记 `needs_ocr`；加密 PDF 标记 `failed`，不会伪装成功。
8. 上传目录 `backend/var/uploads` 不在静态目录内，前端无法直接访问原文件。

## 6. 数据库与迁移

当前迁移版本：`6c51aaf3d15c`（users、resumes）。

从零重建（需要超级管理员执行一次）：

```sql
CREATE ROLE resume_app WITH LOGIN PASSWORD '请替换为强密码';
CREATE DATABASE resume_platform WITH OWNER resume_app ENCODING 'UTF8' TEMPLATE template0;
CREATE DATABASE resume_platform_test WITH OWNER resume_app ENCODING 'UTF8' TEMPLATE template0;
```

`backend/.env` 需要配置：

```dotenv
DATABASE_URL=postgresql+asyncpg://resume_app:密码@127.0.0.1:5432/resume_platform
TEST_DATABASE_URL=postgresql+asyncpg://resume_app:密码@127.0.0.1:5432/resume_platform_test
UPLOAD_DIR=var/uploads
MAX_UPLOAD_SIZE_MB=10
```

迁移命令：

```bash
cd backend
.venv/Scripts/python.exe -m alembic revision --autogenerate -m "describe change"
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m alembic check
```

## 8. 下一阶段建议：3b 结构化抽取与人工校正

目标：把 `extracted_text` 变成可诊断的结构化事实库。

后端：

- 新增 `resume_versions` 表：`resume_id`、`version_no`、`parsed_data`（JSONB）、`corrected_data`（JSONB）、`parser_version`、`model_name`、`created_at`。
- 新增 DeepSeek Provider：环境变量控制 Key、Base URL、模型名、超时与重试；JSON 模式 + Pydantic 二次校验。
- 设计结构化字段：基本信息、教育、工作、项目、技能、证书；每段保留 `source_text`，便于事实追溯。
- 解析失败不保存半结构化脏数据；低温度重试一次，仍失败则返回明确错误。
- 接口：`POST /api/v1/resumes/{id}/parse`、`GET /api/v1/resumes/{id}/versions`、`PUT /api/v1/resumes/{id}/versions/{version_no}`。
- 测试：正常解析、模型返回非法 JSON、字段缺失、重试、用户隔离、版本号递增。

前端：

- 解析结果确认页：分区展示字段，允许编辑与重新保存版本。
- 显示解析模型、版本号与时间；低置信字段提示人工核对。
- 保存后进入诊断入口（阶段 4）。

验收：同一份 PDF 可生成结构化版本，人工修改后保存为新版本；所有字段可追溯到原文，不出现原简历不存在的事实。

> 3b 需要 DeepSeek Key；如果没有 Key，可以先实现 Provider 接口与假 Provider 测试，但无法完成真实解析验收。
