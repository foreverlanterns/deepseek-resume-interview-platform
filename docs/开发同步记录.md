## 1. 项目基线

- 课题：基于 DeepSeek 的智能简历诊断与面试模拟平台设计与实现。
- 前端：Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + ECharts。
- 后端：Python 3.13 + FastAPI + Pydantic v2 + SQLAlchemy 2 + Alembic。
- 数据库：PostgreSQL 17，正式方案不使用 SQLite。
- AI：DeepSeek 独立 Provider，接口、模型名、密钥全部走环境变量。
- 部署：Docker Compose + Nginx，MVP 不使用 Redis。

### 1.1 不可违背的约束

1. 四维诊断总分由程序按固定权重合成：格式 15%、完整度 20%、关键词 25%、JD 匹配 40%；LLM 只输出语义判断与证据，不直接给总分。
2. 修改示例禁止编造技能、公司、项目、证书或量化指标；缺失事实必须提示用户补充。
3. 每道面试题保存来源，例如 `resume:project[0]`、`jd:required_skill[2]`、`general:behavior`。
4. 不实现视频面试、表情识别、社区、UGC 题库、企业招聘端。
5. 前端只使用 TypeScript，不写纯 JavaScript。
6. API Key 只放后端 `.env`，不得提交；数据库只允许 PostgreSQL。
7. 历史对比只在同岗位、同面试类型、同 `rubric_version` 下进行，并保存 `prompt_version` 与模型名。
8. `reference/` 只读；复制 Apache-2.0 / MIT 代码必须保留许可证、NOTICE 并标注修改，优先重写。

### 4.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/resumes/upload` | `multipart/form-data`，字段名 `file`；返回 201 + 详情 |
| GET | `/api/v1/resumes` | 当前用户简历列表，按上传时间倒序，最多 100 条 |
| GET | `/api/v1/resumes/{id}` | 详情与 800 字文本预览 |
| DELETE | `/api/v1/resumes/{id}` | 删除记录与文件，204 |

错误码：

- 401：未登录或 Token 无效。
- 400：扩展名正确但内容不是有效 PDF/DOCX。
- 413：超过 `MAX_UPLOAD_SIZE_MB`（默认 10 MB）。
- 415：不是 PDF/DOCX（图片、DOC、TXT 等）。
- 404：简历不存在，或属于其他用户。

### 4.5 校验与安全设计

1. 文件类型以扩展名 + 文件头双重校验：PDF 必须以 `%PDF-` 开头；DOCX 必须是含 `word/document.xml` 与 `[Content_Types].xml` 的 ZIP。
2. 客户端 `Content-Type` 不参与判定；数据库 `mime_type` 由扩展名归一。
3. 存储路径只由 `user_id` / `resume_id` / 固定文件名组成，不使用用户文件名，避免路径穿越；文件名仅用于展示并已清洗。
4. 所有查询都带 `user_id` 条件；跨用户访问统一返回 404，不暴露资源是否存在。
5. 删除时先删除数据库记录，再在确认路径位于上传根目录内后递归删除简历目录。
6. 文本清洗移除 NUL、统一换行、压缩空白，并截断至 200,000 字符，保护数据库与后续 LLM 调用。
7. 扫描版 PDF（文本少于 50 字符）标记 `needs_ocr`；加密 PDF 标记 `failed`，不会伪装成功。
8. 上传目录 `backend/var/uploads` 不在静态目录内，前端无法直接访问原文件。

Provider 约定：

- 请求 `POST https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`。
- 抽取时显式 `thinking: {"type": "disabled"}`，启用 `response_format: {"type": "json_object"}`，temperature 0.1（修复重试为 0）。
- 429 / 5xx / 网络异常按 `deepseek_max_retries` 指数退避重试；4xx 不重试。
- 模型输出先经 `ParsedResume` 校验；不合法时带错误提示重试一次，仍失败则记失败版本。
- Prompt 要求每条教育 / 工作 / 项目 / 证书 / 奖项提供逐字 `source_text`，禁止推断或编造事实。
- 文本超过 60,000 字符时截断，并在 Prompt 中标记；完整文本仍保存在 `resumes.extracted_text`。

### 5.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/resumes/{id}/parse` | 调用 DeepSeek 生成新版本；201 |
| GET | `/api/v1/resumes/{id}/versions` | 版本列表，按版本号倒序 |
| GET | `/api/v1/resumes/{id}/versions/{version_no}` | 版本详情，含 `parsed_data`、`corrected_data`、`effective_data` |
| POST | `/api/v1/resumes/{id}/versions/{version_no}/corrections` | 以某版本为基础保存人工校正，生成新版本；201 |

错误约定：

- 404：简历或版本不存在 / 不属于当前用户。
- 409：简历没有可解析文本（如扫描件 `needs_ocr`）。
- 502：模型调用或结构校验失败；同时保存 `failed` 版本。
- 503：`DEEPSEEK_API_KEY` 未配置；不生成版本。

### 5.4 版本语义

- 解析成功：`status=parsed`，`parsed_data` 为模型结果，`corrected_data=null`。
- 解析失败：`status=failed`，`parsed_data=null`，`error_message` 记录原因；前端可看到失败历史。
- 人工校正：基于 `version_no=N` 创建 `N+1`，`status=corrected`，`parsed_data` 复制原模型结果，`corrected_data` 保存修改后的完整结构，`base_version_no=N`。
- `effective_data = corrected_data or parsed_data`，后续诊断 / 面试使用该字段。
- 记录 `parser_version`、`prompt_version`、`model_name`，保证结果可追溯。

### 6.3 评分规则

- 固定权重：格式 15%、完整度 20%、关键词 25%、JD 匹配 40%；`rubric_version=rubric_v1`。
- 格式（100 分）：姓名+联系方式 20、标题/简介 10、教育 20、工作/项目 20、技能 15、日期一致性 15。
- 完整度（100 分）：基本信息 20、教育 20、工作 20（无工作但有项目计 10）、项目 15、技能 15、证书/奖项/语言 10。
- 关键词（100 分）：必备技能权重 2、加分技能权重 1、关键词权重 1；按命中权重占比计算；英文关键词按词边界匹配，避免 Java 命中 JavaScript。
- JD 匹配（100 分）：DeepSeek 对每条要求返回 `met / partial / missing`，程序按 `1 / 0.5 / 0` 与要求权重合成，不使用模型自报分数。
- 总分：`格式×0.15 + 完整度×0.20 + 关键词×0.25 + JD 匹配×0.40`，保留两位小数。
- 修改示例：每条包含原文、问题、建议、改写示例、理由；模型输出需通过结构校验。
- 事实护栏：原文摘录必须在简历中可找到；改写示例出现原文没有的数字时，自动降级为 `needs_user_input`；无法核对原文时标记 `needs_review`。

## 10. 下一阶段建议：阶段 5 模拟面试

目标：基于结构化简历 + JD 生成带来源的面试题，逐题评价，必要时追问，最终生成报告。

后端：

- 新增 `interview_sessions`：`user_id`、`resume_id`、`resume_version_no`、`jd_id`、状态、题目数量、`rubric_version`、`model_name`、`prompt_version`、开始/结束时间。
- 新增 `interview_questions`：`session_id`、顺序、来源（`resume:work[0]` / `jd:required_skill[1]` / `general:behavior`）、题目、出题理由、期望要点（JSONB）、回答、五维评分（JSONB）、反馈、追问题目、创建时间。
- 出题：从简历条目、JD 要求、通用行为题三类抽取，去重并控制数量；每题必须保存来源。
- 评价五维：相关性、专业正确性、结构、证据、表达；程序合成总分，LLM 只给证据与反馈。
- 追问：根据回答缺口触发，最多两级；追问也保存来源与父子关系。
- 接口：创建面试、获取当前题、提交回答、获取反馈、结束并生成报告、历史列表。
- 测试：来源标记、题目去重、空回答、追问上限、跨用户隔离、模型非法输出、报告一致性。

前端：

- 面试房间：题目来源标签、回答输入、提交、即时反馈、进度、追问。
- 报告页：总分、五维评分、逐题明细、弱项与建议；可复用 ECharts 雷达图。
- 历史记录：按简历版本、岗位、`rubric_version` 对比。

验收：每道题可追溯到简历条目或 JD 要求；五维评分与报告可复现；同一 `rubric_version` 下可比较。

> 5 的题目质量与评价准确性依赖真实模型；可以先用假 Provider 完成接口、状态机与 UI，真实联调仍需要 Key。
