配合 `docs/验收清单.md` 使用，全部为虚构数据，可直接上传。

| 文件 | 说明 | 预期结果 |
|---|---|---|
| `01_简历_后端开发_林舟.docx` | 主样本，669 字，含教育、工作、2 个项目、4 组技能、证书 | 文本提取成功，状态 `extracted` |
| `02_简历_前端开发_周晴.docx` | 第二份简历，369 字，用于列表、筛选与账号隔离对照 | 文本提取成功 |

| `05_岗位JD_后端开发.txt` | 岗位原文，复制到“岗位描述”的 `raw_text` | 必填技能含 Docker、Kafka |
| `权限验证.py` | 自动注册 A/B 账号并跑 24 项越权检查 | 预期全部 PASS，约 90 秒 |

## 岗位字段建议

- 标题：后端开发工程师
- 公司：云启科技
- 必填技能：Python、PostgreSQL、Docker、Kafka
- 加分技能：FastAPI、Redis
- 关键词：SQLAlchemy、Nginx
- 职责：负责交易与订单后端服务的设计、开发与维护
- 任职资格：本科及以上，3 年以上后端开发经验

简历 A 有意不写 Docker 与 Kafka，用来观察关键词缺失和 JD 匹配未满足项。

## 关于扫描版 PDF

`03_扫描版简历_无文本层.pdf` 是把文字渲染成图片后重新生成的 PDF，没有文本层，所以会进入 `needs_ocr`。这是阶段 3 的已知边界，不属于缺陷；如果答辩时需要演示 OCR，应提前说明当前版本未接入 OCR。

## 清理

脚本会留下 `permcheck.*` 临时账号。清理命令见 `docs/验收清单.md` 附录 B。
