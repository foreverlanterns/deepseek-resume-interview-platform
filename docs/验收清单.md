# 系统验收清单

> 适用环境：<http://localhost:8080>（Docker Compose 容器，`ENVIRONMENT=production`）
> 对照版本：`main` 提交 `5bad7e0`，镜像构建于 2026-11-20
> 使用方式：按第 7 节顺序执行，在“结果”列填写 `P`（通过）/ `F`（不通过）/ `S`（跳过），失败项记入第 6 节。

## 0. 先回答三个问题

**1）现在直接访问 8080 测试，对吗？**

对。8080 是 Nginx + 后端 + PostgreSQL 的容器环境，和答辩时一致，应该以它为准。
注意：容器数据库与本地开发库（5173 + 8000）是两套数据，容器里目前只有 2 个早期验证账号和 1 份测试简历，你的新账号看到的是干净数据。

**2）功能之外还要做权限验证吗？**

要。本系统的核心设计之一是“所有数据按 `user_id` 隔离”，论文的安全性与测试章节需要证据。但不需要手工点二十次：`docs/验收材料/权限验证.py` 会自动跑 24 项越权检查，约 90 秒。浏览器侧只需补 3 项跳转/登出检查。

**3）需要边验证边截图吗？**

需要，但只截第 5 节列出的 10 个状态。截图要来自 8080、同一个演示账号、同一组简历和岗位，论文里的图才连贯。已有 `docs/assets/screenshots/` 的 7 张图是容器化之前拍的，可以先用；如果时间允许，建议按本清单重拍替换。

## 3. 权限与数据隔离验收

### 3.1 自动检查（24 项）

在项目根目录执行：

```bash
backend/.venv/Scripts/python.exe docs/验收材料/权限验证.py
```

脚本会注册 A/B 两个临时账号，由 A 创建简历、岗位、诊断和面试，再由 B 逐项尝试越权。脚本共 24 项：5 项数据准备（DATA-01—05）+ 19 项权限检查；下表 P-01—P-19 由脚本覆盖，P-20—P-22 需手动补。预期最后一行：

```text
合计 24 项：PASS 24，FAIL 0
```

| 编号 | 检查内容 | 预期 | 方式 |
|---|---|---|---|
| P-01 | 未携带 Token 访问接口 | 401，响应头含 `WWW-Authenticate: Bearer` | 自动 |
| P-02 | 注册账号 A | 201 | 自动 |
| P-03 | 注册账号 B | 201 | 自动 |
| P-04 | 同一邮箱大写形式重复注册 | 409“该邮箱已注册” | 自动 |
| P-05 | 错误密码与不存在账号 | 都是 401，提示完全一致 | 自动 |
| P-06 | 篡改 JWT 签名 | 401 | 自动 |
| P-07 | B 读取 A 的简历 | 404 | 自动 |
| P-08 | B 读取 A 的简历版本 | 404 | 自动 |
| P-09 | B 删除 A 的简历 | 404，且 A 仍能读到 | 自动 |
| P-10 | B 读取 A 的诊断 | 404 | 自动 |
| P-11 | B 读取 A 的面试 | 404 | 自动 |
| P-12 | B 给 A 的题目作答 | 404 | 自动 |
| P-13 | B 生成 A 的报告 | 404 | 自动 |
| P-14 | B 用 A 的简历创建诊断 | 404 | 自动 |
| P-15 | B 用 A 的简历创建面试 | 404 | 自动 |
| P-16 | B 的简历列表 | 不含 A 的简历 | 自动 |
| P-17 | B 的成长概览 | 简历/诊断/面试均为 0 | 自动 |
| P-18 | 上传文件名 `../../evil.pdf` | 201，文件名被清洗为 `evil.pdf` | 自动 |
| P-19 | 直接访问 `/uploads/probe.pdf` | 不返回 PDF 内容（只返回前端页面或 404） | 自动 |

### 3.2 已知限制（不算缺陷，论文需说明）

- JWT 无服务端黑名单：退出登录只清除浏览器 Token，旧 Token 在过期前仍可能通过接口校验。生产环境应加短过期时间与刷新机制。
- 上传目录没有单独的下载接口，文件只能由后端读取，前端不暴露真实路径。
- 容器数据库与开发库隔离；`/uploads` 路径由 Nginx 交给 SPA fallback，因此返回 HTML 而不是 404，但不会泄露文件内容。

严重级定义：

- **阻断**：主流程无法继续（登录、上传、诊断、面试打不开）。

## 附录 C：常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 诊断/解析返回 503 | 容器没有加载 `DEEPSEEK_API_KEY` | 检查 `.env.docker`，重建 api：`docker compose --env-file .env.docker up -d api` |
| 诊断超过 1 分钟 | 模型正常耗时 40—80 秒 | 不要重复点击；超时已配置为 120 秒 |
| 上传扫描版 PDF 正常，超过 10MB 报 413 | 上传上限 10MB | 压缩 PDF 或调整 `MAX_UPLOAD_SIZE_MB` |
| 刷新子页面 404 | Nginx 未加载 SPA fallback | 确认使用 `frontend/nginx.conf` 构建的 web 镜像 |
| 8080 看不到之前在 5173 的数据 | 容器库与开发库独立 | 在 8080 重新上传，或导入开发库数据 |
| 扫描 PDF 一直“需 OCR” | 当前版本未接入 OCR | 论文中作为后续工作说明，不计入缺陷 |
