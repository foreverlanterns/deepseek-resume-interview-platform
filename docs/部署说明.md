# 部署说明

本文档描述如何用 Docker Compose 在本机或服务器上启动整套系统。

## 1. 架构

```text
浏览器
  │  http://<host>:8080
  ▼
web（Nginx）
  ├── /            静态前端（Vue 构建产物，SPA history fallback）
  └── /api/        反向代理到 api:8000
                       │
                       ▼
                    api（FastAPI + Alembic）
                       │  postgresql+asyncpg
                       ▼
                    db（PostgreSQL 17）

命名卷：
  pgdata  → PostgreSQL 数据目录
  uploads → /app/var/uploads（原始简历文件）
```

- 浏览器只访问 `web`，前后端同源，不依赖 CORS。
- `api` 不映射宿主机端口，只在 Compose 内部网络暴露 8000。
- `db` 不映射宿主机端口；如需调试可临时加 `ports`。
- `api` 容器启动时先等待数据库，再执行 `alembic upgrade head`，成功后启动 uvicorn。

## 2. 前置条件

- Docker Engine 24+ 与 Docker Compose v2。
- 至少 4 GB 可用内存（前端构建阶段较吃内存）。
- 可用端口：`8080`（可通过 `WEB_PORT` 修改）。

## 3. 首次部署

```bash
cp .env.docker.example .env.docker
```

编辑 `.env.docker`：

- `DB_PASSWORD`：数据库密码，建议只用字母、数字、`-`、`_`。
- `SECRET_KEY`：至少 32 位随机字符串，生成命令：

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

- `DEEPSEEK_API_KEY`：需要真实模型能力时填写；留空时诊断/面试接口返回 503，其余功能正常。
- `WEB_PORT`：默认 8080。

启动：

```bash
docker compose --env-file .env.docker up -d --build
```

查看状态：

```bash
docker compose --env-file .env.docker ps
```

三个服务都应为 `healthy`：

- `db`：`pg_isready`
- `api`：`/api/v1/health/ready` 返回 200
- `web`：Nginx 首页可访问

## 4. 验证

```bash
curl -fsS http://127.0.0.1:8080/api/v1/health | head
curl -fsS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/
```

预期：

- 健康检查返回 `status=ok`、`database=ok`。
- 首页返回 200，未登录时前端跳转到 `/auth`。

浏览器打开 <http://localhost:8080>，注册账号后按以下顺序验证：

1. 上传 PDF/DOCX 简历。
2. 进入结构化页解析或人工校正。
3. 创建岗位并执行四维诊断。
4. 创建模拟面试并逐题作答。
5. 结束面试后生成复盘报告。
6. 在成长页查看趋势与弱项。

## 5. 常用运维

```bash
# 查看日志
docker compose --env-file .env.docker logs -f api
docker compose --env-file .env.docker logs -f web

# 重启单个服务
docker compose --env-file .env.docker restart api

# 停止（保留数据卷）
docker compose --env-file .env.docker down

# 停止并删除数据卷（会清空数据库与上传文件）
docker compose --env-file .env.docker down -v
```

### 升级

```bash
git pull
docker compose --env-file .env.docker build
docker compose --env-file .env.docker up -d
```

`api` 启动时会自动执行未应用的迁移。

### 备份

```bash
# 数据库
docker compose --env-file .env.docker exec -T db \
  pg_dump -U resume_app -d resume_platform -Fc > backup_$(date +%Y%m%d).dump

# 上传文件
docker run --rm -v resume-platform_uploads:/data -v "$PWD":/backup alpine \
  tar czf /backup/uploads_$(date +%Y%m%d).tar.gz -C /data .
```

### 恢复

```bash
docker compose --env-file .env.docker exec -T db \
  pg_restore -U resume_app -d resume_platform --clean --if-exists < backup_YYYYMMDD.dump

docker run --rm -v resume-platform_uploads:/data -v "$PWD":/backup alpine \
  sh -c "rm -rf /data/* && tar xzf /backup/uploads_YYYYMMDD.tar.gz -C /data"
```

> 恢复前先停止 `api`，避免迁移或写入冲突。

## 6. 配置项

| 变量 | 默认值 | 说明 |
|---|---|---|
| `POSTGRES_DB` | `resume_platform` | 数据库名 |
| `POSTGRES_USER` | `resume_app` | 应用数据库账号 |
| `DB_PASSWORD` | 必填 | 数据库密码 |
| `SECRET_KEY` | 必填 | JWT 签名密钥，生产环境至少 32 位 |
| `WEB_PORT` | `8080` | 宿主机映射端口 |
| `CORS_ORIGINS` | `http://localhost:8080` | 同源部署时通常不需要修改 |
| `DEEPSEEK_API_KEY` | 空 | 留空时智能接口返回 503 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | DeepSeek 模型名 |
| `MAX_UPLOAD_SIZE_MB` | `10` | 单文件大小限制 |
| `LOG_LEVEL` | `INFO` | 后端日志级别 |

## 7. 安全注意事项

- 不要提交 `.env.docker`、`backend/.env`、数据库卷或上传文件。
- 部署前必须更换开发数据库密码与 `SECRET_KEY`。
- `ENVIRONMENT=production` 时，配置校验会拒绝弱 `SECRET_KEY` 与 `DEBUG=true`。
- 当前 Compose 未配置 HTTPS；公网部署应在 `web` 前增加反向代理与证书（Caddy / Nginx / 云负载均衡）。
- 上传文件只保存在服务端卷中，不通过静态目录直接暴露；下载/预览均需登录。
- 建议限制服务器防火墙，只开放 `WEB_PORT`。

## 8. 常见问题

**api 一直不健康**

```bash
docker compose --env-file .env.docker logs api
```

常见原因：`DB_PASSWORD` 含 `@`、`:` 等 URL 特殊字符；`SECRET_KEY` 少于 32 位；迁移失败。

**web 启动但接口 502**

检查 `api` 是否 healthy，以及 Nginx 是否能解析 `api` 服务名：

```bash
docker compose --env-file .env.docker exec web wget -qO- http://api:8000/api/v1/health
```

**上传大文件返回 413**

同时检查：

- Nginx `client_max_body_size 12m`
- 应用 `MAX_UPLOAD_SIZE_MB`

**数据库迁移失败**

进入 api 容器手动执行：

```bash
docker compose --env-file .env.docker run --rm --entrypoint alembic api current
docker compose --env-file .env.docker run --rm --entrypoint alembic api upgrade head
```
